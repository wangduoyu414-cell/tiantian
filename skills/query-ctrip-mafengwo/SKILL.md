# 携程与马蜂窝按需查询

把请求转成有来源、适用条件明确的信息。上游负责方案、预算分配和是否放宽条件；本技能负责查询、核验与返回缺口。遵循当前浏览器工具说明及已有授权，不提交订单、询价或旅客资料，不联系商家或修改网络设置。

## 运行前提

使用当前 Codex 已提供、能读取动态页面并操作查询条件的浏览器工具，先按其说明选择浏览器；不假定另一台电脑具有相同工具、标签或网站登录状态。缺少浏览器控制能力时返回具体缺口，不把搜索摘要当作动态报价。网站要求登录时按当前工具规则处理；历史测试会话不代表当前已登录。

## 对齐问题与边界

识别对象/业务、所求字段、硬条件、偏好、允许来源、结果数量和查询预算；接受自然语言，不强制填表。

- 仅补问会改变所求答案的缺参。日期不影响地址；人数可能影响总价、入住资格或足量库存，但不一定影响时刻和参考单价。无歧义的日期转成明确年月日；有实质歧义才询问。
- 缺参只阻断依赖部分。向上游返回待补输入；直接面向用户时合并询问，同时继续独立部分。预算的币种、每人/每间/每晚/全程口径不能混用。
- 不暗改硬条件或把偏好升级为硬条件。为替代方案改日期、站点、预算或人数，由上游决定。
- 指定对象只查该对象。候选发现未指定数量时最多返回 3 项，不凑数；明确数量以请求为目标，未证实项另列线索，不计为满足项。

每个独立查询目标在开始时确定，默认预算 5 分钟，显式时间预算覆盖默认值。从首次查询动作计时，发现、恢复及两站补查共享，不因换词、切站或重新拆分重置。够用即停；到时不发起新查询动作，在途操作按工具自身超时结束后收尾。更多结果不自动取消预算；如实返回未覆盖部分。此默认值只控制成本，不证明覆盖充分或查询失败。

## 选入口，按缺口补查

用户指定的来源和对象链接优先；否则选当前最直接的有效入口。默认携程优先酒店、机票、火车票条件查询，马蜂窝可补目的地资料、攻略、门票商品和酒店报价。实际页面决定能力，不保证某站必有字段。

访问某站前，按需读取其参考：

- [携程：入口、证据区块与陷阱](references/ctrip.md)
- [马蜂窝：入口、证据区块与陷阱](references/mafengwo.md)

只有明确要求比较、关键字段缺失、冲突或路径受阻时才启用另一站，只补相关缺口。指定单站不擅自换站。必要时可借搜索引擎定位两站页面，摘要只作线索。事实来源限于两站；站内供应商要记录，继续站外查询不属于默认范围。

## 以证据决定下一步

共同循环：明确缺什么 → 找相关区块 → 核对实际条件 → 读取所需证据 → 判断已足够、需补查或应结束。

- 核对业务区已加载，以及导航、筛选或展开报价后相关对象、日期、人数/间数、机场/站点和条件仍有效。URL 参数或输入文字不能单独证明条件生效。
- 按区块取证。同页广告、相近推荐和“未满足全部要求”不能当精确匹配；每项硬条件判为满足、不满足或未证实。
- 任何区块已包含本次所需的产品身份、实际条件和事实，即可作为证据；火车列表信息够用就不必深入。只为缺失的必要信息进入详情或展开条款。
- 名称、简介、日历和起价用于发现；资料区回答基础属性；具体产品及条款回答条件报价；攻略和点评提供历史经验。后一类信息不能升级为当前商家承诺。
- 点击以实际效果为边界：展开产品可以，创建订单或提交联系信息不在查询范围内。足以回答就停止深入。

## 保持事实与报价的含义

只取所求字段及避免误解必需的限定，不为每次查询收集全套字段。

- 跨站先核对同一对象的名称、城市、地址/位置；同名同品牌不足以合并，不能确认就分开。
- 报价绑定实际日期、人数/间数、房型或席别、供应商和适用资格。不同价案的价格、早餐、退改不能拼接；保留会员、新客等限制。
- 保留原始价格标签、币种、单位和已知费用范围。起价、均价、人均、含税价、页面总价分开；未知税费/总价不补齐。需要估算时单列假设和计算，不写成可成交总价。
- 分别记录请求数量、实际查询数量和页面余量。单间查询显示剩余多间，不证明这些房间均可同价购买；不同价案余量不能相加。已出现的单间/单人价可作参考，注明条件差异，不计作满足团队需求的报价。
- 每组事实/价案带 URL、注明时区的读取时间、资料/条件报价/用户内容等来源性质及必要区块或短原文；同源同次读取可共用证据。不保存无关账户信息或默认抓整页。
- 区分读取时间、内容更新时间和出行日期。退改等截止时间保留原文，时区不明不补成确定时间点；页面今天更新不证明每条政策今天核实。
- 冲突先核对对象、条件、价案和时间，仍不能解释则并列来源，相关硬条件为未证实，不按站名裁定真伪。
- 新一轮动态报价需新查询；同轮同条件可复用。条件变化只使依赖它的动态结论失效，独立静态事实保留。读取时间不是保价期限。

## 恢复或交回

先检查实际状态，再根据新证据恢复；同一原因恢复一次仍无进展就结束该路径。相同的无副作用操作，仅为明确的瞬态故障假设重试一次。失败记录在两站补查间保留，不循环刷新、枚举猜测地址或重复检索。

| 观察 | 处理与返回边界 |
|---|---|
| 加载中、局部空白、导航超时 | 有界等待并观察真实页面，不立即重开或判无结果 |
| 条件未生效、结构变化 | 根据当前页面恢复并复核；仍不一致记“未成功应用”，仅页面明确声明限制时称“不支持” |
| 明确空结果 | 条件生效且业务区完成加载后，才称“该站该条件未返回匹配项”，不自动放宽 |
| 登录、验证码、扫码、403或网络错误 | 记录具体阻断；依工具规则和已有授权处理或交接，允许时补另一站；不当成无商品，不绕过访问控制 |
| 字段缺失或矛盾 | 展开相关说明或补查对应字段，仍无证据则保留未知/冲突 |

恢复失败只影响依赖它的结论。保留实际条件下可读的参考事实；不要为了消除缺口废弃已得信息，也不要把未知填成否定。

## 返回给调用方

面向用户用简短文字或表格；上游要求结构化时沿用其格式，并保持以下语义。仅填写相关字段，不为无关业务填空。

| 组 | 内容 |
|---|---|
| `query` | 请求条件、页面实际条件及影响结论的差异 |
| `items` | 对象、所求事实、独立价案、逐项硬条件满足/不满足/未证实 |
| `evidence` | 事实/价案对应的来源、读取时间、性质和必要区块 |
| `gaps` | 缺失、冲突、阻断或待补输入；继续所需的信息或动作 |
| `coverage` | 已查来源、实际检查范围及未遍历/达预算等边界 |
| `status` | `complete`、`partial` 或 `blocked`，相对本次请求解释原因 |

完成度、条件匹配、页面售卖状态、需求数量核验分别表达。页面可订/售罄/未开售/抢票或预约/未知，只限定于对应价案和实际条件，不代表锁定库存。

必需字段或明确要求的匹配数量不足时不能报完成；未证实项可作线索，不满足项说明排除原因。限定搜索的真实空结果可回答“是否找到”，但不能满足“给出3个匹配项”。只求参考单价时，无关的团队库存未知不阻止完成；没有可用结果且查询受阻时报告 `blocked`。是否到预算不决定完成度，不声称穷尽搜索或全网最低。
