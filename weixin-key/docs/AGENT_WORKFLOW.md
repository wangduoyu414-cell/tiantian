# 新电脑／Agent 辅助本机微信导出

更新：2026-09-13 UTC。适用于能在用户本机执行命令的 Agent，不依赖某个厂商的专有 API。

## 交付目标与当前边界

用户最新选择：**先交付可由 Codex、WorkBuddy 等本机 Agent 使用的工具和完整说明；完整 GUI 自动链路可以后置。** 必须能从新机器、无本项目配置和缓存开始，获取本人账号材料、提取数据并导出；不能把旧机器缓存复用当成新机取钥成功。

当前已经有 Windows 本机真实取钥、22库认证、受保护缓存及主库整库解密证据。**2026-09-27 第二台独立电脑（Weixin 4.1.15.13）端到端已跑通**：取钥、缓存离线复用、全量导出（含图片解密、发送者/方向/会话名解析）。操作决策树以 `skills/wechat-export/SKILL.md` 为准；本文档保留命令契约细节。详见同目录 `IMPLEMENTATION_STATUS.md`。

### 不同的新机情形

| 情形 | 应走的方向 | 不可混淆 |
|---|---|---|
| 新电脑已有本人微信、本人登录后的本地库，无工具缓存 | 新建本机账号配置，核对版本/进程/账号，限定只读采集、逐库认证、本机保护缓存 | 是“首次取钥”，不是从旧电脑拷密钥 |
| 本机已有可用的受保护缓存 | 先逐库复验缓存，再离线快照 | 不重复扫描微信内存 |
| 只拷了加密 DB，没有本机可用材料 | 寻找本人已有的授权材料或回到能取得材料的本人环境 | 加密文件本身不保证能恢复密钥 |
| 拷了其他 Windows 用户/机器的 DPAPI 配置 | 原文件保留；在新路径初始化，再在当前授权环境获取材料 | 不保证可跨机解保护，不自动降级成明文 |
| 新增库、盐/密钥变化 | 重新验证覆盖范围，只处理确实缺失的部分 | 当前仅缓存 per-salt 派生密钥，不能自动派生所有未来新库 |
| 未知微信构建/架构 | 记录实际模块信息，做静态适配分析和有界验证 | 静态候选不等于已兼容；不能承诺任意未来版本 |
| 公用/陌生电脑上有其他人的账号 | 不处理其材料；确认本人账号及本机操作授权 | 本工具不是远程获取他人数据的工具 |

Windows 用户保护行为参考 Microsoft `CryptProtectData` 文档；域漫游等特例也不应成为可移植性假设。项目不提供凭据迁移或绕过用户保护功能。官方文档地址：`https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata`。

| `material-probe.exe --verify-cache` | 已有，受保护缓存逐库认证，可附私有快照/结构检查 | 首页面认证不等于每个库整库解析成功 |

不使用旧 `setup` 作为无条件兜底。旧采集路径仍有开放问题；主动关闭/重启/调试/注入路径仍隔离。不要把环境变量设为“允许”来绕过。

## 获取程序

当前为开发源码和内部候选，**没有本指南对应的已发布便携包**。已有经验证的可执行文件时无需本机 Go；无可执行文件时，可由本机 Agent 用 `go.mod` 指定的 Go 1.26.5 在仓库根构建：

```powershell
# 仅开发构建；先确认当前目录就是所选项目根目录。
go version
go build -trimpath -o .build\agent-tools\weixin-key.exe ./cmd/weixin-key
go build -trimpath -o .build\agent-tools\material-probe.exe ./cmd/material-probe-diagnostic
```

第二个命令目前要求 Windows；加密快照的内嵌引擎证据限 Windows amd64。检查实际使用的 Go 版本，而非只看启动器路径；宿主启动器可能自动转入不同版本的工具链。必要依赖安装应由本机 Agent 在授权范围内处理，不需要用户手工写 Go。

后续便携包仅允许包含可执行文件、必要许可、指南、支持矩阵和哈希清单。**禁止整目录打包仓库、用户配置、备份、聊天、内存、`.build` 历史日志或本机绝对路径。** 便携的是程序与说明，不是旧机器秘密缓存。

## 本机执行步骤

下面变量是占位模板，不是可以原样执行的真实机器参数。Agent 必须在新电脑重新观测，不复制旧任务的 PID、创建时间、模块哈希、账号路径和配置哈希。

### 1. 明确选择与只读检查

确认仅处理本人账号。优先从用户明确给出的目录或微信的文件管理设置确定包含 `db_storage` 的账号根目录；多账号不得取第一个。用户登录/扫码和系统权限确认由用户完成。不要全盘读取聊天来“找账号”。

设置本次作业的绝对路径：

- `$cli`：本机选定的 `weixin-key.exe`。
- `$probe`：与本次候选绑定的 `material-probe.exe`。
- `$dbRoot`：选定账号根目录，不是 `db_storage` 或 `xwechat_files` 总目录。
- `$account`：用户确认的账号标识；只是配置绑定，不能代替进程/数据库认证。
- `$cfg`：当前用户本机独立账号配置路径。
- `$out`：源目录之外的导出位置。

```powershell
& $cli doctor --db-root $dbRoot --config $cfg --out $out --pretty
```

`doctor` 不继承 `WECHAT_CLI_*` / `WX_MCP_*` 中的旧账号或密钥，也不读默认配置。未指定路径就返回 `not-selected`，不猜测。输出可能含账号路径，保留本地，不当作匿名遥测上传。

关键 JSON：

- `source.status=selected-not-authenticated`：目录结构符合，不代表已登录/取钥。
- `config.status=absent`：可进入新配置流程；父目录仍需人工/Agent确认建立。
- `config.status=present-not-read-or-verified`：文件存在但未读取，不能据此声称缓存可用。
- `output.status=path-only-checked`：仅做物理路径隔离检查，未验证空间、可写性、DACL或快照一致性。
- `ready_for_export=false`：当前真实导出前置条件未整体验收，不能因诊断 exit0 自动开始全量导出。

退出码：0=诊断完成，不等于取钥/导出成功；1=所选路径无效；2=参数错误。缺失选择仍是诊断结果，Agent必须检查状态字段。

### 2. 仅在配置不存在时初始化

选择当前用户可写的本地目录，位于微信源目录之外，先建立配置的父目录。推荐每账号独立目录；不要复用其他人的配置。源根和配置父路径的各级目录不得包含junction/符号链接等reparse point；不要使用UNC、映射网络盘或设备路径。路径不符合时另选实际本地目录，不自动改权限或解开链接。

```powershell
& $cli init-account --db-root $dbRoot --account $account --config $cfg --pretty
```

- 只写账号元数据，**没有密钥**，不访问微信进程。
- 显式路径，不读取或保存环境里的口令。
- 短暂固定源根/配置父目录及其祖先的只读句柄，在同一个已核对的目录身份上检查隔离并写入；不通过旧路径重新打开或自动创建父目录。目录被占用导致共享冲突时明确失败，不放宽检查。
- 使用独占新建模式打开目标，不替换已有文件。创建后、写入任何元数据前设置并验证当前用户私有 DACL。
- 不迁移或读取旧目标；锁忙立即失败，不在锁内扫描微信。
- 同版本Windows配置writer先使用当前用户范围的命名互斥量协调，再取原配置文件锁。初始化在协调范围内取得并释放目录pins；普通配置更新等待，显式缓存更新/初始化遇忙失败。这样不会在未持协调锁时短暂阻断另一个合作writer的原子替换。没有新增磁盘上的全局配置或持久系统设置；不要并行混用不参与协调的旧版EXE。
- 正常保留同目录协作锁文件，不创建初始化临时文件；不自动删除其他文件。失败需检查锁/目标的实际状态，不能递归清空账号目录。
- **初始化是无秘密元数据的独占创建，不是原子发布。** 取消、写失败或强杀可能留下空/不完整目标；即使失败也保留该文件，不自动删除/覆盖。在协作锁之外读取时，其他程序也可能暂时读到未完成metadata，应按不可用处理。
- JSON 的 `applied=true` 仅表示目标已创建，不表示写完；之后权限、读回、句柄清理或取消失败仍保留true。只有命令 exit0 且 `metadata_verified/private_file=true` 才算初始化完成。`applied=true`但未完成时先检查实际状态，选一个新配置文件路径可安全重试；不要盲改旧目标。
- CLI的Ctrl+C/SIGTERM请求取消并等待当前初始化worker完成清理和状态输出；重复中断不另起作业。关闭控制台、任务管理器强杀或系统异常仍可能没有完整JSON，必须核对文件实际状态。
- 这一步没有 DPAPI 密文，也不提供秘密字段输入；后续已认证材料写缓存时才进入既有DPAPI保护、备份及原子替换流程。没有改变真正密钥缓存的原子写入契约。

### 3. 有缓存先验证；无有效缓存才考虑采集

在本机计算实际配置 SHA256，不读取/显示内容：

```powershell
$configSHA = (Get-FileHash -LiteralPath $cfg -Algorithm SHA256).Hash
& $probe --verify-cache --root $dbRoot --cache-config $cfg --cache-config-sha256 $configSHA
```

仅元数据的新配置在这里不能通过，这是预期，不是取钥失败。拷来的受保护配置解不开时保留它，选择新路径，不修改用户保护或将秘密打印到对话框。

已有缓存全覆盖并通过后，跳过实时采集。失败应区分未初始化材料、错误账号、不可解保护、缺库/轮换、源变化及读取错误，不能统一解释为“再扫描一次”。

### 4. 新机首次材料采集：显式且有界

复用 `MATERIAL_PROBE.md` 的已实现参数契约。Agent先核对本机真实进程、创建时间、可执行路径、实际加载模块路径/哈希、所选账号数据库持有者及主库相对路径，再执行静态检查：

```powershell
& $probe --inspect --module $module --sha256 $moduleSHA
```

静态结果只是假设。匹配候选并不自动证明版本受支持；不匹配则保留诊断，进入适配，不盲目改RVA或扩大预算。

本人本机范围及这些副作用已获授权、身份核对通过后，现有实时入口可以组合私有临时快照与显式缓存：

```powershell
& $probe --module $module --sha256 $moduleSHA --pid $targetPID `
  --created $createdUTC --root $dbRoot --exe $weixinExe --primary-db $primaryDB `
  --snapshot-check --scratch $scratch `
  --cache-verified --cache-config $cfg --cache-config-sha256 $configSHA
```

`$scratch` 是源目录之外的已存在本机目录。静态/实时检查、库认证、快照、私有目录或清理任一不通过，不应报告缓存成功。命令内部采集截止为协作式90秒，快照组合整体为协作式8分钟；Agent要监督**自己启动的helper**，不能把这些预算说成操作系统强制时限。禁止按微信进程名结束进程。强杀或系统异常后可能有临时明文，须按本次精确目录恢复清理，不能声称必然自动删除。

命令退出、配置实际状态核对后，重新计算配置哈希，使用**新的独立程序调用**验证缓存全部命中。保存的证据只有候选/文件哈希、时间、计数、状态及清理结果，不含密钥、口令或聊天。

### 5. 快照、解析、导出

先离线私有快照/结构验证，再完成真实发送者、压缩标记和原始字节的有界语义核验。当前 Windows 正式导出 staging 已改为创建时设置并回读当前用户私有 DACL，并加入源库/WAL容量下限检查；消息解析会识别新版 packed local type、保留压缩/二进制原始字节，但 numeric `real_sender_id` 的联系人目录关联仍需独立验证。

**当前可以在已验证缓存和本批 parser/staging 检查通过后运行 `export`，但如果 manifest 为 `partial`，它不是“完整解析完成”。** 压缩正文、内部 numeric sender 或未提取附件会被保留为可审计的 partial 记录，不能被误报为普通文本。该入口目前通过进程环境选择配置：

```powershell
# 仅为解析/staging验收之后的调用契约；不是当前全量导出授权门。
# 应在干净子进程环境中只设置本次配置，清除旧 WECHAT_CLI_* / WX_MCP_*
# 材料覆盖。不要改用户/系统持久环境变量，不把口令放在命令行。
$env:WECHAT_CLI_CONFIG = $cfg
& $cli export --db-root $dbRoot --account $account --out $out --pretty
```

最终必须对账分库快照、原始记录、标准消息、未知/失败消息、去重/修订、附件状态、Markdown与manifest；`partial` 不算完整导出完成。当前CLI并没有小样本导出的范围开关，不要编造 `--limit` 等参数。
如需在不生成聊天输出的情况下核验当前 17 列消息库，可使用 material-probe 的离线 `--verify-cache --snapshot-check --semantic-check`；它只返回行数、SQLite 运行时类型、WCDB_CT 标记、时间单位和 sender 非空统计，不返回正文、联系人姓名或密钥。

## 新机验收与后续实现顺序

1. **本批基础入口**：doctor 与 init-account；空配置、环境污染、禁止覆盖、取消、锁忙、写后读回及既有受保护写入兼容的合成检查。合成空HOME不是第二台电脑。
2. **真实导出关键路径**：私有staging、真实发送者/压缩/时间适配、小样本对账和全库导出。不能让诊断功能替代这个目标。
3. **Agent首次采集编排**：复用当前诊断器，把目标发现/确认、版本记录、参数准备、helper监督、缓存验收与失败恢复做成统一命令；不另外发明取钥算法或自动启用主动路径。
4. **便携交付和新机验证**：只携带程序和说明，先以无旧配置的新Windows用户做隔离测试，再在第二台独立电脑上从首次材料获取到正式导出，并验证第二次纯缓存；保留精确候选、实际支持矩阵和失败证据。新用户测试不能替代独立电脑验收。
5. **扩展矩阵**：多安装/多账号、无微信/未登录、未知构建、权限拒绝、低磁盘、源库变化、新分片和轮换。不能静默跨账号或重复抓全部库。
6. **跨平台**：Mac仍需本机材料获取、Keychain、加密快照和真机端到端证据；交叉编译只证明构建。GUI/安装器不再阻塞Agent优先交付，但不能把未实现的Mac功能算完成。
